# Static AWS blueprint — deployment is not authorized

The three concrete modules model separate lifecycles: private network/endpoints, PostgreSQL/MSK, and application identity/ECS/HTTPS ingress. `environments/static` uses the AWS6.69.0 schema, dummy credentials, a zero account ID, invalid example hosts/images and two mock-provider tests. These inputs are deliberately non-deployable. No account credentials, real account plans, resources or Terraform deployment operations were used.

Run `validate-static.ps1 -Terraform C:/absolute/path/to/terraform.exe` for formatting, provider installation without backend initialization, schema validation and explicit plan-only mocked tests. The script rejects unmocked test providers and deploy-mode tests. `.terraform.lock.hcl` pins the provider; `.terraform`, state, saved plans and private material stay outside Git. Terraform1.16.6 and AWS6.69.0 were verified for these checks.

The tests assert private/encrypted/deletion-protected PostgreSQL, authenticated TLS Kafka, three private/non-root/read-only runtime definitions with bounded shutdown, and secret references. Schema/mocked graph acceptance is not evidence of IAM, network reachability, capacity, cost, cloud recovery or service availability.

Before any separately authorized cloud work, replace every placeholder and re-review the account-specific design. Current gaps include private connectivity to Redis/Mongo/OIDC (no internet/NAT fallback), real digest-pinned ECR images and certificate, KMS/secret policies and SCRAM identities/association/ACLs, application SCRAM authentication configuration, RDS CA trust, dedicated runtime SQL users/grants and an approved cloud migration process. The local migration CLI intentionally refuses remote databases. External Redis/Mongo/OIDC are required dependencies, not provisioned or validated by this model. ECS temporary-volume permissions, restore, rolling upgrades and multi-AZ behavior remain unverified. The static graph must not be described as ready to launch.

MSK4.2.x is listed by [AWS's supported Kafka versions](https://docs.aws.amazon.com/msk/latest/developerguide/supported-kafka-versions.html). The [pinned provider resource documentation](https://raw.githubusercontent.com/hashicorp/terraform-provider-aws/v6.69.0/website/docs/r/msk_cluster.html.markdown) specifies SCRAM/TLS settings; this differs from the laboratory SASL/PLAIN profile. [HashiCorp provider mocking](https://developer.hashicorp.com/terraform/language/tests/mocking) enables these checks without creating infrastructure. No cost or sizing claim follows from the example instance/storage choices.
